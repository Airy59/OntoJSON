REST API Documentation

Base URL: http://localhost:5001/api
Content-Type: application/json

Transformation Endpoints

POST /api/transform

Transform a single ontology to JSON Schema

{
    "source": "https://example.org/ontology.ttl",
    "format": "turtle",
    "language": "en",
    "config": {
        "rules": ["class_to_object", "labels_to_titles"]
    }
}

Response:

{
    "success": true,
    "schema": { ... },
    "metadata": {
        "classes_count": 10,
        "properties_count": 25
    }
}

POST /api/transform/multiple

Transform multiple ontologies into a composite JSON Schema

{
    "sources": [
        "https://example.org/onto1.ttl",
        "https://example.org/onto2.ttl"
    ],
    "composite_metadata": {
        "title": "Combined Ontology",
        "description": "Merged ontologies"
    }
}

Asynchronous Task Management

POST /api/tasks

Create a new transformation task for async processing

{
    "sources": ["https://example.org/ontology.ttl"],
    "config": {
        "language": "en"
    }
}

Response:

{
    "task_id": "f75f07bf-1ca0-4376-b306-5496dce16aca",
    "status": "pending",
    "message": "Task created successfully"
}

GET /api/tasks/{task_id}

Get the status of a transformation task

Response:

{
    "task_id": "f75f07bf-1ca0-4376-b306-5496dce16aca",
    "status": "completed",
    "progress": 100,
    "message": "Transformation complete",
    "result": {
        "success": true,
        "schema": { ... }
    }
}

POST /api/tasks/{task_id}/cancel

Cancel a running task

GET /api/tasks

List all tasks

Query Parameters:

  • status - Filter by status (pending, in_progress, completed, failed)
  • limit - Maximum number of results (default: 20)
  • offset - Offset for pagination

Configuration Management

GET /api/configurations

List available transformation configurations

POST /api/configurations

Create a new configuration preset

{
    "name": "my-config",
    "description": "Custom configuration",
    "rules": {
        "class_to_object": true,
        "labels_to_titles": {
            "enabled": true,
            "language": "en"
        }
    }
}

GET /api/health

Health check endpoint

Error Handling

All error responses follow this format:

{
    "error": "Error message describing what went wrong",
    "details": {
        "field": "Additional error details"
    }
}

Common HTTP Status Codes

  • 200 OK - Request successful
  • 202 Accepted - Task created for async processing
  • 400 Bad Request - Invalid request parameters
  • 404 Not Found - Resource not found
  • 500 Internal Server Error - Server error

Example: Full Workflow

# 1. Create a transformation task
curl -X POST http://localhost:5001/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"sources": ["https://example.org/ontology.ttl"]}'

# 2. Check task status
curl http://localhost:5001/api/tasks/TASK_ID

# 3. Get the result when completed
curl http://localhost:5001/api/tasks/TASK_ID/result

# 4. Generate sample data
curl -X POST http://localhost:5001/api/generate/abox \
  -H "Content-Type: application/json" \
  -d '{"schema": RESULT_SCHEMA, "instance_count": 5}'
